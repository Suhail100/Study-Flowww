## 6. SUBJECT-SPECIFIC AI CHATBOT — ESSENTIAL REQUIREMENT

Implement a chatbot for every subject.

The chatbot is NOT a separate bottom-navigation tab. It belongs inside the selected subject's area.

Expected workflow:

Subjects
→ Select DBMS
→ DBMS Subject Detail
→ Ask AI / Chatbot
→ DBMS Chat

Similarly:

Subjects
→ Select Operating Systems
→ Operating Systems Subject Detail
→ Ask AI / Chatbot
→ Operating Systems Chat

The same reusable chatbot component may be used for every subject, but the conversation must be associated with the correct subject.

### Chatbot requirements

Each subject chatbot should support:

* Asking questions about the subject.
* Explaining difficult concepts in simple language.
* Step-by-step explanations.
* Examples.
* Summarising topics.
* Generating practice questions.
* Helping the user understand mistakes.
* Asking questions based on uploaded subject materials when supported.

The chat header must show the selected subject's name.

Maintain separate conversation histories for different subjects. A DBMS conversation must never appear in the Operating Systems chat.

Store each conversation with the appropriate subject ID.

If the user switches subjects and opens that subject's chatbot, load that subject's conversation or start a new conversation if none exists.

Provide a clear way to return to Subject Detail without accidentally navigating to an unrelated screen.

### AI behaviour

Prepare the chatbot interface and service integration for Gemini AI.

If Gemini is not yet connected:

* Do not pretend that real AI responses are being generated.
* Show a clear setup or unavailable state, or use an explicitly labelled demo mode.
* Keep the chatbot interface ready for the real API integration.

When Gemini is connected, send the selected subject name and relevant context with the user's question.

When uploaded materials are supported, use the selected subject's materials as context rather than mixing materials from other subjects.

Do not expose Gemini API keys in browser JavaScript or public frontend code. Use a secure backend endpoint for AI requests.

### Subject-specific actions

If supported by the existing design, allow the user to:

* Open a document from the subject.
* Ask the chatbot to summarise it.
* Ask questions about its contents.
* Generate practice questions from it.

Do not claim that a document has been analysed unless the backend has actually processed it.
